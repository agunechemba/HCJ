Welcome

Hello, Future Web Developer

A complete course in the language of the web.

This book is a journey through the three technologies that make the web what it is. HTML gives a page its structure — headings, paragraphs, links, images, forms. CSS gives it style — colors, fonts, spacing, layout. JavaScript gives it behaviour — clicks, keypresses, calculations, communication with servers. Alone, each is useful; together, they are the web.

The journey runs in five parts. Book One gets your tools set up and shows you what each language does. Book Two walks you through the HTML elements you'll use on every page you ever build. Book Three teaches CSS from the box model outward. Book Four brings the page to life with JavaScript. Book Five shows you how to lay out pages that look good on any screen.

You do not need fancy software. A text editor, a modern browser, and a curious mind will get you through every chapter. Open a folder. Save a file. Reload the browser. That loop — edit, save, reload, repeat — is the whole secret of web development.

Ready? Let us begin.

Before You Go

  • HTML provides structure; CSS provides style; JavaScript provides behaviour.
  • The browser is your lab — reload early, reload often.
  • You learn to code by writing code, breaking it, and fixing it.
  • Every professional programmer writes bugs every day. You will too. That's fine.

Warm-Up Questions

  1. What's one website you use every day? Try to describe how its structure, style, and behaviour might be built.
  2. What does "reload" do in a browser?
  3. What file extension would you give a web page file?

Getting Started

Tools, browsers, editors, web hosts, and a way of working that will serve you for the whole book.

Book One · Getting Started · Chapter One

Getting Acquainted with HTML, CSS, and JavaScript

What each of the three does, and why the web runs on them.

Every web page you have ever visited is built from three ingredients. HTML (HyperText Markup Language) describes the page's structure — the headings, the paragraphs, the images, the links. CSS (Cascading Style Sheets) describes the page's appearance — the fonts, colors, spacing, layout. JavaScript describes the page's behaviour — what happens when you click a button, submit a form, or scroll to the bottom.

HTML is a markup language, which means it wraps bits of content in tags that describe what each piece is. CSS is a style language, which means it applies rules to those tags. JavaScript is a full programming language — it can store values, make decisions, repeat things, and respond to the user.

You don't need fancy software to build a page. You need a text editor to write the code and a browser to view the result. The browser reads your HTML, applies your CSS, runs your JavaScript, and draws the page you see.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>My First Page</title>
  </head>
  <body>
    <h1>Hello, world!</h1>
    <p>This is my first web page.</p>
  </body>
</html>

Save that code as index.html, open it in your browser, and you have built a web page. That's it. Every complicated site you've ever seen is a longer, richer version of that same structure.

Key Ideas

  • HTML gives structure; CSS gives style; JavaScript gives behaviour.
  • All three live inside a plain text file with an .html extension.
  • The browser reads your code top to bottom and renders the result.
  • You need only a text editor and a browser to get started.

Try It Yourself

  1. Type the sample code into a new file, save it as index.html, and open it in your browser.
  2. Change the <h1> text to your own name and reload.
  3. Add a second paragraph below the first.

Book One · Getting Started · Chapter Two

Getting Ready to Code

Browsers, folders, editors, and the workbench.

Before you write more code, set up your workspace. First, install the four major browsers: Chrome, Edge, Firefox, and — on a Mac — Safari. You don't need all four, but testing in more than one catches problems early.

Second, create a folder on your computer to hold all your web projects. Call it public_html or htdocs — both are traditional names. Inside it, make subfolders for css, js, and images. Keeping files organised is the difference between a project you can maintain and a folder full of mystery.

Third, choose a text editor. The editor that came with your computer — Notepad on Windows, TextEdit on the Mac — will technically do. But the good ones offer syntax highlighting, line numbers, code completion, and previews — and they make the work of writing code much easier. Free options: Visual Studio Code, Notepad++, Brackets, Atom. Paid options: Sublime Text, Nova.

Finally, keep a workbench handy for quick experiments. The WebDev Workbench (or CodePen) lets you type HTML, CSS, and JavaScript into three tabs and see the result instantly — no files, no saving, no reloading. It's a great way to test an idea before committing it to a file.

Key Ideas

  • Install more than one browser for testing.
  • Create a project folder with subfolders for css, js, and images.
  • Use a proper text editor — the features pay for themselves.
  • Use an online workbench for quick experiments.

Try It Yourself

  1. Create your project folder and its three subfolders.
  2. Install Visual Studio Code (or another editor of your choice).
  3. Open the WebDev Workbench and change the background color of the page using the CSS tab.

Book One · Getting Started · Chapter Three

Finding and Setting Up a Web Host

Getting your pages out of your computer and onto the web.

Your web page isn't "on the web" until it lives on a computer that other computers can reach. That computer is called a web server, and the company that runs it is called a web hosting provider.

You have three choices for hosting. Your existing internet service provider may offer space — ask. A free hosting service (like GitHub Pages, Cloudflare Pages, or Netlify) will host static HTML, CSS, and JavaScript files at no charge. A commercial provider will offer more storage, more bandwidth, better support, and a domain name — for a monthly fee.

When shopping for a host, understand the vocabulary: storage space (how many files you can keep), bandwidth (how much data the server can send each month), domain name (like example.com), email, server type, databases, uptime, and tech support.

When you sign up, you get a root directory on the server and a web address. Anything you upload to the root directory is visible at the matching web address. To keep things simple, mirror your local folder structure on the server: if you have a css subfolder on your computer, put a css subfolder on the server too.

Upload your files using FTP (with a client like Cyberduck or FileZilla), your editor's built-in upload feature, or your host's file manager. Then — when you update a file — you don't edit it on the server; you edit the local copy and re-upload.

Key Ideas

  • A page lives "on the web" only when it lives on a web server.
  • Free hosts exist for static files; paid hosts offer more features.
  • Mirror your local folder structure on the server.
  • Upload files with FTP; edit locally and re-upload when you change something.

Try It Yourself

  1. Create a free GitHub account and enable GitHub Pages for a repository.
  2. Upload your index.html from Chapter One and view it at the live URL.
  3. Change the heading, re-upload, and reload the page.

Book One · Getting Started · Chapter Four

Testing and Validating Your Code

Making sure your pages work everywhere — and follow the rules.

Testing on only one browser is the single biggest mistake a new developer makes. Chrome is popular, yes — but visitors will show up using Safari, Firefox, Edge, and a hundred mobile variants. Test on Chrome, Firefox, Edge, and Safari. For mobile, use Chrome on Android and Safari on iOS, plus an emulator or real device for each.

If you can't run all those browsers locally, use an online cross-browser tester — BrowserStack, LambdaTest, or Comparium — which lets you run your page against a farm of real browsers.

Separately from testing, validate your code. A validator checks your HTML and CSS against the official specifications. Valid code doesn't guarantee a beautiful page — but it guarantees the browser can parse your page correctly, which means any remaining problem is with your design, not your syntax.

The W3C runs free validators: validator.w3.org for HTML and jigsaw.w3.org/css-validator for CSS. For JavaScript, use jshint.com or an editor extension like ESLint. Modern editors will flag errors inline as you type — a huge timesaver.

Key Ideas

  • Test in multiple browsers — never just one.
  • Use an online tester if you can't install every browser.
  • Validate HTML and CSS with the W3C's free tools.
  • Validate JavaScript with JSHint or ESLint.

Try It Yourself

  1. Validate your index.html at validator.w3.org. Did it pass?
  2. Deliberately remove a closing tag. Validate again. What error do you get?
  3. Run your JavaScript through JSHint. Do you see any warnings?

Book Two · Learning HTML Basics · Chapter Five

Building Good Bones: Structuring the Page

Paragraphs, headings, breaks, and the semantics of page layout.

Plain text pasted into an HTML file comes out as one undifferentiated blob. HTML's first job is to give that text structure — to tell the browser what each chunk of content is.

The simplest structure is the paragraph, created with <p> and </p>. The six heading tags — <h1> through <h6> — create a hierarchy from most important to least. A line break <br> forces a new line without paragraph spacing; a horizontal rule <hr> draws a line across the page to mark a thematic break.

Then come the semantic page elements — the tags that describe page regions rather than text chunks. <header> holds the site title and logo. <nav> holds the navigation links. <main> holds the page's primary content. <article> holds a self-contained composition. <section> holds a thematic chunk of an article. <aside> holds tangential content — a sidebar or pull quote. <footer> holds contact info and copyright. And <div> is a generic, non-semantic container for anything else.

<body>
  <header>
    <h1>My Site</h1>
  </header>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
  </nav>
  <main>
    <article>
      <h2>A Post</h2>
      <p>Some text.</p>
    </article>
  </main>
  <footer>&copy; 2027</footer>
</body>

Finally, comment your code. HTML comments use <!-- ... --> and are ignored by the browser, but invaluable to the human (often future-you) reading the source. Use comments to explain why something is the way it is, not just what it is.

Key Ideas

  • Use <p> for paragraphs, <h1>–<h6> for headings, <br> for line breaks, <hr> for thematic breaks.
  • Semantic tags — header, nav, main, article, section, aside, footer — describe the region of a page.
  • Use <div> only when no semantic tag fits.
  • Comment your HTML with <!-- ... -->.

Try It Yourself

  1. Build a page with a header, nav, main, one article with two sections, and a footer.
  2. Add an <hr> between two sections of the article.
  3. Add an HTML comment above your <nav> explaining what its links do.

Book Two · Learning HTML Basics · Chapter Six

Adding Links, Lists, and Other Text Tidbits

Emphasis, quotation, links, lists, and the small tags that carry big meaning.

HTML has an entire vocabulary for marking up text with meaning. Use <em> for stress (browsers render it italic) and <strong> for importance (browsers render it bold). These are semantic — they describe the reason for the styling, not just the styling itself.

For quotations, use <blockquote> for the long, indented type and <q> for short quotes that live inside a sentence. For links, the element is <a> with an href attribute pointing at the destination:

<a href="https://www.w3.org/">The W3C</a>

You can also link within a page by giving any element an id attribute and pointing your <a> at #that-id.

For lists, use <ul> for bulleted (unordered) lists and <ol> for numbered (ordered) lists. Inside, each item is wrapped in <li>. For name-value pairs — definitions, glossaries, term sheets — use a description list: <dl>, with <dt> for the term and <dd> for the description.

And do get to know the small semantic tags: <abbr> for abbreviations, <code> for snippets of code, <kbd> for keyboard input, <mark> for highlighted text, <sub> and <sup> for subscript and superscript, <s> for struck-through text, and <pre> for text that needs whitespace preserved. They cost nothing, and they give your page meaning that search engines, screen readers, and future-you can use.

Key Ideas

  • <em> for stress, <strong> for importance — semantic, not just visual.
  • Links use <a href="...">; internal links target #id.
  • Lists: <ul>, <ol>, <li>, plus <dl>/<dt>/<dd> for name-value pairs.
  • Many small tags (abbr, code, kbd, mark, sub, sup) add meaning cheaply.

Try It Yourself

  1. Build a bulleted list of three favourite books, with each title marked up in <em>.
  2. Add a numbered list of five steps for something you do every morning.
  3. Create a description list with three terms and their definitions.

Book Two · Learning HTML Basics · Chapter Seven

Working with Images, Video, and Other Media

Bringing pictures, sound, and motion into your page.

To place an image on a page, use the <img> element — and always include an alt attribute describing what the image shows:

<img src="images/flower.jpg"
     alt="A macro photo of an ant on a flower"
     title="Flower and Ant">

The src gives the path to the image file. The alt gives a text alternative read by screen readers, shown when images fail to load, and used by search engines. The optional title gives a tooltip on hover.

For images that need a caption, wrap the image in <figure> and the caption in <figcaption>. For clickable images, wrap the whole <img> in an <a> tag. To align an image vertically with surrounding text, use CSS's vertical-align property.

For video, use the <video> element. For content from YouTube, Vimeo, or Dailymotion, use their embed code — usually an <iframe> pointing at the video URL. For your own video files, use:

<video src="videos/bear.mp4"
       poster="images/bear.png"
       width="640" height="480"
       controls
       loop>
</video>

The controls attribute shows the play/pause/volume bar; poster shows a still image before playback; loop restarts when the video ends; autoplay starts automatically. For multiple formats, use <source> elements — the browser picks the first one it can play.

For audio, the pattern is nearly identical, with the <audio> element and MP3 files as the safe default.

Key Ideas

  • Insert images with <img src="..." alt="..."> — always include alt text.
  • Use figure and figcaption for images that need captions.
  • Embed third-party video with the provider's <iframe> code; use <video> for your own files.
  • Audio uses the same pattern with <audio> and MP3.

Try It Yourself

  1. Add an image to your page with both src and alt.
  2. Wrap the image in a <figure> with a <figcaption>.
  3. Embed a YouTube video using the provider's share/embed code.

Book Two · Learning HTML Basics · Chapter Eight

Building Tables with Your Bare Hands

Rows, columns, headers, captions, and the fine art of making data readable.

When your data is naturally tabular — rows of records, columns of fields — HTML's table elements exist to display it. A table is built from a container <table>, sections <thead>, <tbody>, and <tfoot>, rows <tr>, header cells <th>, and data cells <td>.

<table>
  <caption>Funny Food-Based Town Names</caption>
  <thead>
    <tr>
      <th>Town</th>
      <th>State</th>
      <th>Population</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Candy Kitchen</td><td>New Mexico</td><td>59</td>
    </tr>
    <tr>
      <td>Hot Coffee</td><td>Mississippi</td><td>2,586</td>
    </tr>
  </tbody>
</table>

Style tables with a little CSS: border-collapse: collapse removes the double borders; padding gives cells breathing room; text-align and vertical-align position content within cells. Use caption-side: bottom to move the caption below the table.

One important modern rule: never use tables for page layout. That technique died years ago — CSS Grid and Flexbox (Book Five) handle layout far better, and tables used for layout wreak havoc on accessibility.

Key Ideas

  • Tables have table, thead, tbody, tfoot, tr, th, td, and caption.
  • Use th for headers, td for data.
  • Style with border-collapse, padding, and alignment properties.
  • Use tables for data — never for page layout.

Try It Yourself

  1. Build a table of your three favourite films, with columns for title, year, and director.
  2. Add a <caption> describing the table.
  3. Style the table with collapsed borders and 8-pixel cell padding.

Book Two · Learning HTML Basics · Chapter Nine

Using Forms to Make a Page Interactive

Text fields, checkboxes, radio buttons, dropdowns, and pickers.

A form is the web page's way of gathering input. It lives inside a <form> element and consists of fields — text inputs, checkboxes, radio buttons, dropdowns — plus a submit button.

The <input> element, with its type attribute, covers most of the ground. type="text" gives a single-line text box. type="email", type="url", and type="tel" give validation-aware boxes. type="number" gives a spin box. type="password" masks its input. type="search", type="date", type="time", and type="color" give you specialised controls. type="checkbox" and type="radio" give toggles and single-choice groups.

<form>
  <label for="email">Email:</label>
  <input id="email" type="email" name="email"
         placeholder="you@example.com">

  <label>
    <input type="checkbox" name="subscribe">
    Subscribe to the newsletter
  </label>

  <button type="submit">Send</button>
</form>

Pair every field with a <label> — either wrapping the field or referring to it via for and id — so screen readers know what each field means and users can click the label to focus the input.

For longer text, use <textarea>. For dropdowns, use <select> with <option> children. For grouping related fields, use <fieldset> with a <legend> caption.

Key Ideas

  • Wrap fields in a <form> and end with a submit button.
  • Use <input type="..."> for most fields; use textarea for long text.
  • Always pair fields with <label> — for accessibility and usability.
  • Use fieldset and legend to group related fields.

Try It Yourself

  1. Build a form with a name field, an email field, and a submit button.
  2. Add a group of three radio buttons for "small / medium / large".
  3. Add a textarea for comments and a checkbox for "agree to terms".

Book Two · Learning HTML Basics · Chapter Ten

Making Your Web Pages Accessible

Designing for everyone, not just for people like you.

Accessibility is the practice of building pages that every visitor can use — including the one billion people worldwide who live with some form of disability. Access to the web is a right, not a nicety, and accessible pages also rank better in search results, work better on slow connections, and cost you almost nothing extra to build.

People with visual impairments may use a screen reader — software that reads the page aloud. That software navigates a page by its structure: by its headings, its landmarks, its labels, its alt text. A page built with proper semantic HTML is automatically easier for a screen reader to navigate.

People with motor impairments may use a keyboard instead of a mouse. Test your pages with Tab and Shift+Tab and Enter. Every interactive element — links, buttons, form fields — should be reachable by keyboard.

People with cognitive impairments benefit from consistent layouts, clear instructions, and simple language. And people with colour-blindness or low vision benefit from sufficient contrast between text and background — aim for a contrast ratio of at least 4.5.

Many of the ARIA attributes — role, aria-label, aria-labelledby — exist to add accessibility information to elements that can't otherwise express it. Use them when semantic HTML isn't enough. Then, before you ship, run your page through wave.webaim.org — the Web Accessibility Evaluation Tool — to catch anything you missed.

Key Ideas

  • Accessible pages work for people with visual, auditory, motor, and cognitive differences.
  • Use semantic HTML — it's the single biggest accessibility win.
  • Always include alt text, proper headings, and labelled form fields.
  • Ensure sufficient colour contrast and keyboard navigability.

Try It Yourself

  1. Run your page through wave.webaim.org. What errors and warnings appear?
  2. Navigate your page using only the Tab key. Can you reach every link and field?
  3. Check your text colour against its background at webaim.org/resources/contrastchecker.

Book Three · Learning CSS Basics · Chapter Eleven

Figuring Out the CSS Box Model

Content, padding, border, margin — the four rings of every element.

Every element on a page is surrounded by an invisible box. That box has four layers: the content (the text or image itself), the padding (space inside the box, between content and border), the border (the line drawn around the padding), and the margin (space outside the border, between this box and its neighbours).

.card {
  padding: 16px 20px;
  border: 1px solid #ccc;
  margin: 20px 0;
  border-radius: 8px;
}

Elements come in two flavours. Block elements (p, div, h1) start on new lines and fill the width of their parent. Inline elements (a, span, em) flow along with text. The display property flips between them — display: inline-block gets you the best of both, and display: none hides an element entirely.

By default, an element's width and height describe the content only — padding and border get added on top, which can blow past your intended total width. Fix that with box-sizing: border-box, which makes width include padding and border. Put it at the top of your stylesheet:

* {
  box-sizing: border-box;
}

One quirk to watch for: collapsing margins. When two vertical margins meet, the browser uses the larger of the two, not their sum. This can surprise you. The fix is usually to add padding, or to use Flexbox (Book Five), where margins don't collapse.

Key Ideas

  • Every element is a box with content, padding, border, and margin.
  • Block elements stack; inline elements flow with text; display controls which.
  • Use box-sizing: border-box so width includes padding and border.
  • Vertical margins collapse — the larger one wins.

Try It Yourself

  1. Give a div some padding, a border, and a margin. Inspect it in the dev tools to see the box model.
  2. Add * { box-sizing: border-box } to your stylesheet and refresh.
  3. Create two stacked elements with adjacent margins and observe the collapse.

Book Three · Learning CSS Basics · Chapter Twelve

Getting to Know the CSS Selectors

Picking out exactly which elements get which styles.

A CSS rule has two parts: a selector that identifies which elements to style, and a declaration block that lists the styles to apply. The selector is the targeting mechanism — the more precise it is, the more control you have.

The basic selectors are: type (p, h1) for every element of a kind; class (.warning) for every element with that class attribute; id (#main-title) for the one element with that id; and the universal selector (*) for every element on the page.

p        { color: navy; }
.warning { background: gold; }
#hero    { font-size: 3rem; }
h2.title { border-bottom: 2px solid; }

You can also select based on relationships. The descendant combinator (a space) targets any element matching the right selector that lives inside the left selector: article p matches every paragraph inside any article. The child combinator (>) matches only direct children: nav > a matches links that are immediate children of a nav. The adjacent sibling combinator (+) matches the element immediately following another: h2 + p matches paragraphs that come right after a heading. The general sibling combinator (~) matches any later sibling: h2 ~ ul matches any list that comes after a heading in the same parent.

Attribute selectors match based on the presence or value of an attribute: a[href^="https://"] matches any link whose URL starts with HTTPS. img[alt=""] matches images with empty alt text. They're precise and often underused.

Key Ideas

  • Basic selectors: type, class (.), id (#), universal (*).
  • Descendant ( ), child (>), adjacent sibling (+), general sibling (~).
  • Attribute selectors match by the presence or value of attributes.
  • Combine selectors for precision: h2.title targets only h2 elements with that class.

Try It Yourself

  1. Style every p with a different font size, then every .intro with a larger one.
  2. Style nav > a with padding and no underline.
  3. Use h2 + p to give the paragraph right after each heading a bold first word.

Book Three · Learning CSS Basics · Chapter Thirteen

Pseudo School: Learning Pseudo-Classes and Pseudo-Elements

Styling what's not on the page: states, positions, and generated content.

A pseudo-class styles an element based on its state or position — things the HTML doesn't directly express. The :hover pseudo-class fires when the mouse is over the element. :focus fires when a keyboard focus is on it. :visited and :link target links you've clicked or not. :first-child and :last-child target position-based children. :nth-child(even) — famous for zebra-striping tables — targets every second child.

a:hover           { color: hotpink; }
input:focus       { outline: 2px solid teal; }
tr:nth-child(even){ background: #f4f4f4; }
p:first-of-type   { margin-top: 0; }

Form-related pseudo-classes style fields based on their validation state: :valid, :invalid, :required, :optional, :in-range, :out-of-range, :disabled, :enabled, :checked.

A pseudo-element is different: it creates a fake element that doesn't exist in your HTML but can be styled with CSS. ::before and ::after create a first or last child inside a parent element. ::first-letter styles the first letter of a block (for drop caps). ::first-line styles the first line, however long it happens to be at the current viewport width.

.external-link::after {
  content: " ↗";
  color: gray;
}

.article > p::first-letter {
  font-size: 3rem;
  float: left;
  line-height: 0.85;
  padding-right: 6px;
}

The content property must appear inside ::before and ::after, even if its value is the empty string. Don't put essential content in a pseudo-element — assistive technology may not read it.

Key Ideas

  • Pseudo-classes (:hover, :focus, :nth-child()) style by state or position.
  • Form pseudo-classes style fields based on their current validation state.
  • Pseudo-elements (::before, ::after, ::first-letter) create fake sub-elements.
  • Never put essential content in a pseudo-element.

Try It Yourself

  1. Style every link's :hover state with a new colour and underline.
  2. Zebra-stripe a table using :nth-child(even).
  3. Give the first paragraph of an article a drop cap with ::first-letter.

Book Three · Learning CSS Basics · Chapter Fourteen

Making CSS Make Sense

Comments, resets, debugging, and the rules that govern which styles win.

Comment your CSS with /* ... */. Use comments to explain why a rule exists, and to mark out sections in a long stylesheet — general styles, typography, layout, component styles. Comments help future-you understand what present-you was thinking.

A CSS reset is a small stylesheet added at the top that overrides the browser's default styles. Different browsers used to disagree wildly about things like heading sizes and list spacing; the popular reset normalize.css smooths most of those over while preserving useful defaults. Load it before your own styles:

<link rel="stylesheet" href="css/normalize.css">
<link rel="stylesheet" href="css/styles.css">

When CSS doesn't behave the way you expect, open the browser's dev tools (F12 or Cmd-Option-I). Right-click any element and choose Inspect. The Styles panel shows every rule applying to that element, in order of importance — strikethrough means overridden. The Computed panel shows the final values the browser has calculated after all the cascading.

The cascade is the algorithm the browser uses to decide, when several rules try to style the same property, which one wins. Three factors determine it, in order: origin and importance (author vs. user vs. browser; normal vs. !important), specificity (how narrow the selector is), and source order (the later rule wins when everything else ties). Specificity breaks into three buckets: IDs, classes/pseudo-classes/attributes, and element types. Higher bucket wins; if buckets tie, later rule wins.

Key Ideas

  • Comment your CSS and organize it into sections.
  • Load a reset like normalize.css before your own styles.
  • Use the browser's dev tools to inspect which rules apply.
  • The cascade resolves conflicts by importance, specificity, then source order.

Try It Yourself

  1. Add section-marker comments to your stylesheet.
  2. Download normalize.css and link it before your main stylesheet.
  3. Right-click a paragraph in your page and study its Styles panel. Which rule wins a specific property, and why?

Book Three · Learning CSS Basics · Chapter Fifteen

Taking the Measure of CSS

Pixels, percentages, ems, rems, and the viewport units.

CSS needs units, and it has quite a few. The most common are px (pixels), % (percentages), em (relative to the current element's font size), rem (relative to the root element's font size), and the viewport units vw, vh, vmin, and vmax (1/100 of the viewport's width, height, smaller dimension, larger dimension).

Which to use? For fonts, use rem — never px. Pixels override the user's own font-size preference, which is an accessibility failure. rem respects it. For spacing (margins and padding), rem keeps proportions consistent with the text. For layout width, use percentages or viewport units so the layout adapts to the screen.

You can also perform calculations in CSS with calc():

article {
  width: calc(100% - 15rem);
}

And you can clamp a value between a minimum and maximum — very useful for fluid typography:

body {
  font-size: clamp(1rem, 0.9rem + 0.5vw, 1.25rem);
}

Other functions — min(), max() — let you choose the smallest or largest of a set of values. Together they turn CSS from a fixed grid of numbers into a responsive system that does much of the adapting for you.

Key Ideas

  • Use rem for fonts and spacing; use percentages or viewport units for layout.
  • Never set font sizes in px — it breaks the user's font-size preference.
  • calc() lets you combine units with arithmetic.
  • clamp(), min(), and max() keep measurements within bounds.

Try It Yourself

  1. Change a pixel font size to a rem value.
  2. Use calc() to make an element 100% wide minus 40 pixels.
  3. Use clamp() to keep a heading between 1.5rem and 3rem.

Book Three · Learning CSS Basics · Chapter Sixteen

Fancifying Pages with Colors and Backgrounds

Naming, mixing, and layering colour — plus gradients.

CSS accepts colour in several forms. Use keywords like tomato, steelblue, rebeccapurple for quick picks. Use RGB codes (#ff6347) or the rgb() function (rgb(255 99 71)) for precise mixing. Use hsl() (hsl(9deg 100% 64%)) when you want to reason about hue, saturation, and lightness — which is much easier than reasoning about red-green-blue mixes.

.alert {
  color: #ff6347;
  background-color: hsl(9deg 100% 96%);
  border-left: 4px solid tomato;
}

For backgrounds, use background-color for a flat colour, or background-image for a picture. To layer multiple backgrounds (a logo on top of a photo), separate them with commas — the first is on top. Control the position, size, and repeat with background-position, background-size, and background-repeat.

Gradients are generated images. linear-gradient() runs in a straight line; radial-gradient() radiates from a point; conic-gradient() rotates around a centre. You can stack colour stops to define where each colour appears:

.hero {
  background: linear-gradient(135deg,
    #c8553d 0%,
    #d4a94e 50%,
    #2a7f7a 100%);
}

Whatever colour scheme you choose, respect contrast — aim for at least 4.5:1 between text and its background. The browser's dev-tools colour picker will show you the ratio as you adjust the swatch.

Key Ideas

  • Colours can be keyword, hex, rgb(), or hsl() — pick whichever is clearest for the job.
  • Backgrounds can be colours, images, gradients, or layers of all three.
  • linear-gradient(), radial-gradient(), and conic-gradient() generate decorative images.
  • Always verify contrast — aim for at least 4.5:1.

Try It Yourself

  1. Give a div an hsl() background and a matching darker border.
  2. Apply a two-colour linear gradient to your hero section.
  3. Check your text/background contrast with the dev-tools colour picker.

Book Three · Learning CSS Basics · Chapter Seventeen

Taking Your Text Up a Notch with Web Typography

Typefaces, sizes, line heights, and the trinity that makes text a pleasure.

Most of the appeal of a well-designed page comes from typography — not from dramatic imagery, but from getting the small things right. A typeface (Helvetica) is a design; a font (16pt bold Helvetica) is a specific instance. CSS calls the typeface a font family, set with font-family.

body {
  font-family: Georgia, "Times New Roman", serif;
}

Provide a font stack — a comma-separated list of candidates, ending with a generic keyword (serif, sans-serif, monospace). The browser uses the first one available. For greater variety and consistency, use web fonts from a provider like Google Fonts — a single <link> tag in your <head> pulls in the font, and your font-family picks it up.

Then get three things right — the typographic trinity: size, line height, and line length. Set body text at least 1rem (16px), larger if you like — most websites are set too small. Set line-height around 1.5 for readability. Keep line length between 45 and 75 characters, which you can achieve with max-width: 65ch.

p {
  font-size: 1.125rem;
  line-height: 1.6;
  max-width: 65ch;
  margin: 0 auto 1.5em;
}

Then the supporting cast: font-weight for bold or light, font-style: italic for slant, letter-spacing for tracking, text-transform for caps (but never use it to fake headings), text-align for alignment, and hyphens: auto to help justified text. Style links carefully so they stand out from body text; underlined is the safest default.

Key Ideas

  • Set font-family to a stack ending in a generic keyword.
  • Web fonts from Google Fonts give more choice than system fonts.
  • The typographic trinity: size (≥1rem), line height (≈1.5), line length (45–75 characters).
  • Style links to stand out from body text.

Try It Yourself

  1. Link a Google Font and apply it to your page's body text.
  2. Set a max-width of 65ch on your paragraphs.
  3. Adjust your line-height and compare 1.2, 1.5, and 1.8.

Book Four · Building Dynamic Pages · Chapter Eighteen

JavaScript: The Bird's-Eye View

What it does, how it fits, and how to add it to a page.

JavaScript is a full programming language that runs inside the browser. HTML describes content; CSS styles it; JavaScript controls it. With JavaScript you can respond to user actions, modify the page as it's displayed, request data from servers, and validate form input before it's sent.

You attach JavaScript to a page in three ways: an attribute on an element, an inline <script> block, or an external file — the last being cleanest:

<script src="scripts/main.js"></script>

The browser runs a page's JavaScript in order, one statement at a time. Statements end with semicolons (technically optional, best to include). Comments use // for one line, or /* ... */ for a block. Everything between statements that JavaScript ignores is there to help the human reader.

For testing, the browser's Console (F12, then Console tab) is your best friend. Type a snippet and press Enter; the result appears below. Use console.log() from your script to leave notes for yourself in the same place.

console.log("Hello from JavaScript!");
// The Console prints the message and returns undefined (which is fine).

JavaScript is a client-side language — it runs on the user's browser, not the server. That means it can't read files from your computer, can't see other sites' cookies, and can't touch the server's databases directly. That last part is handled by the server, in languages like PHP or Python — which is beyond this book's scope.

Key Ideas

  • JavaScript is a full programming language that runs in the browser.
  • Add it via an attribute, an inline block, or an external file.
  • Comments explain; the browser ignores them.
  • The Console is the fastest place to test and log.

Understanding Variables

Named containers for values — the memory of your scripts.

A variable is a named box in the computer's memory that holds a value. Declare one with let (if the value will change) or const (if it won't). To assign a value, use =.

let score = 0;
const player = "Ada";
score = score + 10;

Variables come in a few data types: numbers (42, 3.14, -7), strings ("hello", 'hello', `hello`), Booleans (true or false), and others like undefined, null, and objects. Strings can hold any text; escape sequences like \n put line breaks inside them.

To name a variable, follow a few rules: start with a letter or underscore, then any combination of letters, digits, and underscores. No spaces, no reserved words (like let, if, function). Names are case-sensitive. Good variable names are descriptive: accountBalance beats x. Convention in JavaScript is camelCase — start lowercase, capitalize the start of each subsequent word.

let userFirstName = "Ada";
let userAge = 12;
const maxRetries = 3;

Prefer const by default; use let only when the value must change. Avoid var in new code — it has odd scoping rules that let and const fixed.

Key Ideas

  • Declare with let (mutable) or const (immutable binding).
  • Types: numbers, strings, Booleans, and more.
  • Names: letters, digits, underscores; no spaces, no reserved words; case-sensitive.
  • Prefer descriptive camelCase names.

Book Four · Building Dynamic Pages · Chapter Twenty

Building Expressions

Arithmetic, comparison, and logic — the operations that make values talk.

An expression is a piece of code that produces a value. Its raw materials are operands (values) and its tools are operators (symbols that combine operands).

Arithmetic expressions combine numbers: +, -, *, /, % (remainder). The + operator doubles as string concatenation, so "Hello, " + "world" produces "Hello, world". Watch out for that: JavaScript will convert numbers to strings if the left side of a + is a string.

const tip = 100 * 0.15;         // 15
const total = 100 + tip;        // 115
const greeting = "Hi, " + "Ada"; // "Hi, Ada"

Comparison expressions use ==, ===, !=, !==, >, <, >=, <=. Prefer the strict forms (===, !==) — they check type as well as value. "5" === 5 is false; "5" == 5 is true. The loose forms cause subtle bugs; avoid them.

"5" === 5   // false
"5" == 5    // true
10 > 4      // true
"a" < "B"   // false (uppercase precedes lowercase in Unicode)

Logical expressions combine Booleans. && (AND) is true only if both sides are true. || (OR) is true if either side is true. ! (NOT) flips the value.

true && false   // false
true || false   // true
!true           // false

When several operators share an expression, JavaScript applies them in order of precedence: arithmetic first, then comparison, then logic. Parentheses override everything, and a good habit is to add them whenever precedence isn't immediately obvious — for clarity, if nothing else.

Key Ideas

  • Expressions combine operands with operators to produce a value.
  • Prefer === and !== over the loose forms.
  • &&, ||, ! are AND, OR, and NOT.
  • Parentheses override precedence; use them when in doubt.

Try It Yourself

  1. Log 2 + 3 * 4 and (2 + 3) * 4. Compare.
  2. Test "10" === 10 and "10" == 10 in the Console.
  3. Write an expression that's true only if two Booleans are both true.

Book Four · Building Dynamic Pages · Chapter Twenty-One

Controlling the Flow of JavaScript

If this, then that. While this, do that.

By default, JavaScript runs top to bottom. But control structures let you make the flow branch and repeat.

The if statement runs a block of code only if a condition is true. The else branch runs when it isn't. Chain else if to test multiple conditions in order. For many discrete cases, switch is clearer and less error-prone:

let greeting;
const hour = new Date().getHours();

if (hour < 12) {
  greeting = "Good morning";
} else if (hour < 18) {
  greeting = "Good afternoon";
} else {
  greeting = "Good evening";
}

Loops repeat a block. while repeats as long as a condition is true. do…while runs at least once, then tests. for bundles three things — where to start, when to stop, how to change — into one line:

for (let i = 1; i <= 5; i++) {
  console.log("Round " + i);
}

Inside a loop, break exits early; continue skips the rest of the current iteration and moves to the next. Both are occasionally useful, but if you find yourself reaching for them often, look for a simpler structure.

The danger in every loop is the infinite loop — a loop whose condition never becomes false. It will freeze the browser tab. Always make sure something inside the loop changes the value that the condition checks. If a page hangs and asks "Stop script?", you've found one.

Key Ideas

  • if / else if / else branch on condition. switch handles many discrete cases.
  • while and do…while loop on condition; for bundles counter and condition.
  • break exits a loop; continue skips to the next iteration.
  • Infinite loops freeze the page — always update the condition inside the loop.

Try It Yourself

  1. Write an if/else that prints "Even" or "Odd" based on a number.
  2. Loop from 1 to 20, printing only the even numbers (i % 2 === 0).
  3. Write a while loop that counts down from 5 to 1 and prints "Blast off!".

Book Four · Building Dynamic Pages · Chapter Twenty-Two

Harnessing the Power of Functions

Write it once. Call it as often as you like.

A function is a named block of code that runs only when you call it. Functions can accept parameters (inputs) and return a value (output). They're the primary tool for avoiding repetition.

function square(x) {
  return x * x;
}

console.log(square(4)); // 16
console.log(square(7)); // 49

You can call a function from anywhere it's in scope. Pass values as arguments in the parentheses. Use return to hand a value back to the caller; without it, a function returns undefined.

Functions can also exist anonymously — with no name. This is useful when the function will be used only once, as a callback passed to another function. Since ES2015, anonymous functions have a shorter form called an arrow function:

const square = (x) => x * x;

// Passing a callback
[1, 2, 3].forEach((n) => console.log(n * 2));

Scope governs where variables are visible. Variables declared inside a function belong to that function; they can't be seen from outside. Declare them outside any function and they become global — visible everywhere. Prefer local scope. Globals leak, collide, and make code harder to reason about.

Recursion is a function calling itself. It's a powerful technique for problems that break into smaller subproblems, but every recursive function needs a stopping condition — otherwise you'll blow the stack.

Key Ideas

  • Functions bundle reusable code and can accept inputs and return values.
  • Arrow functions (=>) are a compact form for anonymous functions.
  • Variables declared inside a function have local scope; those outside have global scope.
  • Recursion needs a stopping condition.

Try It Yourself

  3. Write a recursive function that computes the sum of 1 to n.

Playing with the Document Object Model

Selecting, changing, creating, and reacting — the web page as a data structure.

The Document Object Model (DOM) is the browser's representation of your page as a tree of objects. Every HTML element is a node; every attribute and every piece of text is a node. JavaScript can read from and write to this tree, changing the page after it's been loaded.

To work with an element, you must first select it. The modern, CSS-flavoured way:

const heading = document.querySelector("h1");
const allLinks = document.querySelectorAll("nav a");
const byId = document.getElementById("main-title");

To change an element, set one of its properties. textContent replaces its text; innerHTML replaces its HTML; individual attributes go through setAttribute().

heading.textContent = "Welcome!";
heading.style.color = "navy";
heading.classList.add("highlight");

To create and insert new elements, use createElement and one of append, prepend, before, or after. To remove an element, call remove() on it.

const li = document.createElement("li");
li.textContent = "A new item";
document.querySelector("ul").append(li);

Finally, events make pages reactive. Attach a listener with addEventListener(), and the callback runs whenever that event fires on that element:

document.querySelector("button").addEventListener("click", () => {
  alert("You clicked!");
});

Common events: click, dblclick, mouseover, keydown, keyup, focus, blur, change, submit, scroll. The callback receives an event object — access event.target to know which element was clicked, event.key to know which key was pressed, and call event.preventDefault() to stop the browser's default behaviour.

Key Ideas

  • The DOM is a tree of objects representing the page.
  • querySelector() and querySelectorAll() select elements with CSS syntax.
  • Change elements via textContent, innerHTML, style, and classList.
  • Listen for events with addEventListener().

Working with Arrays

Lists of values, plus the methods that loop, filter, transform, and total them.

An array is an ordered list of values. Create one with square brackets, or with the Array constructor:

const fruits = ["apple", "banana", "cherry"];
const empty = [];
const grid = [[1, 2], [3, 4]];

Access elements with square-bracket notation. Arrays are zero-indexed — the first element is at fruits[0].

Arrays come with powerful iteration methods that take a callback and run it for each element. The four most useful:

const numbers = [1, 2, 3, 4, 5];

numbers.forEach(n => console.log(n));         // Prints each
const doubled = numbers.map(n => n * 2);      // [2, 4, 6, 8, 10]
const evens  = numbers.filter(n => n % 2 === 0); // [2, 4]
const total  = numbers.reduce((sum, n) => sum + n, 0); // 15

For simple iteration, a for…of loop is often clearer than a callback:

for (const fruit of fruits) {
  console.log(fruit);
}

Mutation methods change the array: push() and pop() add or remove at the end; unshift() and shift() at the beginning; splice() removes and inserts in one call. Non-mutating methods return a new array: concat(), slice(), map(), filter(). To search, use indexOf(), find(), findIndex(), or includes(). To sort, sort() — with a comparison callback for numbers, since the default sort is alphabetical.

Key Ideas

  • Arrays are zero-indexed, ordered lists of values.
  • forEach, map, filter, and reduce are the core iteration tools.
  • for…of is often clearer than a callback for plain iteration.
  • push/pop, shift/unshift, splice/slice, sort, find cover most day-to-day array work.

Manipulating Strings, Dates, and Numbers

The three built-in objects every script ends up using.

Strings have a rich set of methods. length tells you how many characters there are. includes, startsWith, and endsWith test for substrings. indexOf finds the position of a substring; slice, substring, and substr extract pieces; split turns a string into an array; replace substitutes text; toUpperCase and toLowerCase change case; trim removes whitespace at the ends.

const email = "ada@example.com";
email.includes("@")          // true
email.slice(0, email.indexOf("@"))  // "ada"
email.split("@")             // ["ada", "example.com"]

Template strings (backticks) let you embed expressions in strings without concatenation — and they span multiple lines:

const name = "Ada";
console.log(`Hello, ${name}!`);

Dates come from the Date object. new Date() gives the current moment; new Date("2027-05-28") gives a specific day. Extract pieces with getFullYear, getMonth (zero-indexed!), getDate, getDay, getHours, and friends. Set pieces with the corresponding set… methods.

const now = new Date();
console.log(now.getFullYear(), now.getMonth() + 1, now.getDate());

Numbers come with the Math object. Math.round, Math.floor, Math.ceil round; Math.abs gives absolute value; Math.max and Math.min pick the largest or smallest from a list; Math.random gives a random decimal between 0 and 1; Math.pow and Math.sqrt do powers and roots. To convert strings to numbers, use parseInt, parseFloat, or the unary +.

Key Ideas

  • Strings have methods for searching (indexOf, includes), extracting (slice, split), and transforming (toUpperCase, replace).
  • Template strings (backticks) embed expressions with ${}.
  • Date represents a moment in time; methods extract or set individual parts.
  • Math gives rounding, min/max, randomness, and powers.

Storing User Data in the Browser

localStorage, sessionStorage, and the JSON that carries objects across the gap.

The Web Storage API gives your scripts a place to save data directly in the user's browser — no server required. There are two storage spaces: localStorage persists until you delete it; sessionStorage clears when the browser tab closes. Both hold key-value pairs as strings.

localStorage.setItem("username", "Ada");
const user = localStorage.getItem("username"); // "Ada"
localStorage.removeItem("username");
localStorage.clear();

You can't store an object directly — only strings. To save a complex structure, convert it to text first with JSON (JavaScript Object Notation). To load it back, parse it.

const prefs = { theme: "dark", fontSize: 16 };
localStorage.setItem("prefs", JSON.stringify(prefs));

const loaded = JSON.parse(localStorage.getItem("prefs"));
console.log(loaded.theme); // "dark"

You can inspect what a page has saved in the browser's dev tools — under Application (Chrome, Edge) or Storage (Firefox, Safari), look for Local Storage and Session Storage. That's where you'll see the keys and values your script has written.

Web storage is per-origin and per-browser. If your user visits in Chrome on Monday and Safari on Tuesday, the data won't follow them. For anything you need across devices — or across many users — you need a server, which is outside this book's scope.

Key Ideas

  • localStorage persists; sessionStorage clears with the tab.
  • Both store strings only — use JSON.stringify and JSON.parse for objects.
  • Clear individual items with removeItem, all items with clear.
  • Storage is per-origin and per-browser.

Try It Yourself

Debugging Your Code

When things go wrong, the tools that help you find out why.

Three kinds of errors exist. Syntax errors are typos in the code — the script never runs. Runtime errors happen while the script is running — usually a reference to something that doesn't exist. Logic errors are when the code runs but produces the wrong answer — the hardest to find because there's no error message pointing at them.

The Console is your first stop. It shows messages, error reports, and output from console.log(). Read the error messages carefully — they usually point to a line number and a file. The browser's console also has an input line where you can run expressions live to test your understanding.

The debugger is your second stop. It lets you pause your code mid-execution, inspect the values of variables, and step through statements one at a time. Set a breakpoint by clicking a line number in the Sources panel. Refresh the page. The browser pauses before that line, showing you the current state of everything.

From there, use Step Over (F10) to advance one line, Step Into (F11) to dive into a function call, Step Out (Shift+F11) to finish the current function and return. Watch your variables in the Scope panel, and add watch expressions to track a specific value as it changes.

const pageFooter = document.querySelector("footer");
const year = new Date().getFullYear();
pagefooter.innerHTML = "Copyright " + year; // Bug: pagefooter vs pageFooter

The most common errors, by frequency: using reserved words as variable names; misspelling variable names; mismatched case (firstName vs firstname); mismatched quotes or brackets; using = instead of ===; referencing elements before they're loaded; infinite loops.

Key Ideas

  • Syntax errors stop the script; runtime errors break it; logic errors produce wrong results.
  • The Console shows errors and logs; the debugger lets you pause, inspect, and step.
  • Breakpoints, watch expressions, and step commands are your tools.
  • Read error messages carefully — they usually point at the problem.

Try It Yourself

  3. Add a watch expression for a variable and watch it change as you step.

Processing Form Data

Wiring up HTML forms to JavaScript behaviour.

HTML forms gather input; JavaScript processes it. To read a text field's value, access its value property. To set it, assign to value. To know which checkbox is checked, read its checked property. To know which radio button in a group is selected, use the :checked selector.

const input = document.querySelector("#email");
console.log(input.value);     // the current text

const box = document.querySelector("#subscribe");
console.log(box.checked);     // true or false

const delivery = document.querySelector(
  'input[name="delivery"]:checked'
);
console.log(delivery.value);

For selection lists, the <select> element exposes selectedOptions — a collection of the currently selected options. Get their values or their display text with .value or .text.

const select = document.querySelector("#hair-style");
const option = select.selectedOptions[0];
console.log(option.value, option.text);

Forms also emit events. The change event fires when a field's value changes; the submit event fires when the form is submitted; focus and blur fire when a field gains or loses focus. Use these to validate input, update the page in real time, and prevent submission until everything is correct.

document.querySelector("form").addEventListener("submit", (e) => {
  e.preventDefault();
  const email = document.querySelector("#email").value;
  if (!email.includes("@")) {
    alert("Please enter a valid email.");
    return;
  }
  console.log("Form data ready to process:", email);
});

The e.preventDefault() call stops the browser from sending the form to the server — which is what we want here, since we're processing entirely in JavaScript. When you're ready to send data to a real server, the form will submit on its own, but that's beyond this book's scope.

Key Ideas

  • Read and set field values via the .value property; check state via .checked.
  • For radio groups and dropdowns, use :checked or selectedOptions.
  • Listen for change, submit, focus, and blur events.
  • Use e.preventDefault() to stop a submit while you process the data.

Try It Yourself

  1. Add a submit handler that prevents default and logs each field's value.
  2. Validate an email field with a simple includes("@") check.
  3. Update a live preview on the page every time the user types in a text field.

Book Five · Looking Good with Layouts · Chapter Twenty-Nine

Exploring Some Layout Basics

Page flow, floats, positioning, and stacking.

By default, the browser lays a page out simply: block elements stack top to bottom; inline elements flow along the text. That's the page flow. Everything else in CSS layout is a way of stepping outside that default.

The oldest such step is floating. Give an element float: left or float: right and it gets pushed to that side of its container, with surrounding text wrapping around it. This is how pull quotes work, and how images float alongside body text. The catch: floated elements are removed from normal flow, so their parent containers may collapse to zero height. The fix is a technique called clearfix — or, in modern code, simply using Flexbox or Grid instead.

.logo { float: left; margin-right: 1em; }

/* Clearfix on a parent */
.clearfix::after {
  content: "";
  display: block;
  clear: both;
}

Positioning gives finer control. The position property takes four useful values beyond static. relative shifts an element from its normal position (without removing its space). absolute positions an element relative to its nearest positioned ancestor, and removes it from flow. fixed pins an element to the viewport — a sticky header. sticky combines relative and fixed — the element scrolls normally until it reaches a specified threshold, then pins.

header {
  position: sticky;
  top: 0;
  background: white;
}

Stacking controls which element appears on top when they overlap. Positioned elements stack in source order, but z-index — an integer — lets you reorder them. Higher z-index appears on top. The tricky part is stacking contexts: once an element creates a new stacking context (which happens, for instance, when it sets position non-statically and z-index to a number), its children can't escape that context — a higher z-index inside the child won't lift it above a sibling of the parent's own stacking level.

Key Ideas

  • Default page flow stacks blocks and flows inlines.
  • Floats break out of flow; clearfix prevents container collapse.
  • position takes relative, absolute, fixed, or sticky.
  • z-index reorders overlapping positioned elements.

Try It Yourself

  1. Float an image to the right of a paragraph and observe the wrapping.
  2. Make a header sticky with position: sticky; top: 0.
  3. Create two overlapping divs and reorder them with z-index.

Getting Fancy with Flexbox

One-dimensional layout that just works.

Flexbox is CSS's tool for laying out items along a single axis — a row or a column. It's the modern way to centre things, distribute space, and make layouts that adapt.

The pattern is always the same: designate a flex container with display: flex, and its children automatically become flex items.

.nav {
  display: flex;
  gap: 1rem;
  justify-content: center;
}

Two properties control the two axes. justify-content aligns along the primary axis (the direction items flow). align-items aligns along the cross axis. Together, setting both to center gives you the famous perfectly-centred box — a feat that used to require arcane hacks.

.centered {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

Direction changes with flex-direction — row (default), column, or the reversed forms. Wrapping (when items overflow) is controlled by flex-wrap: wrap. Gaps between items come from the gap property.

On individual items, flex: grow shrink basis controls sizing. flex: 1 on all children makes them expand equally to fill the container. flex: 0 0 200px pins an item to a fixed size. flex: 1 0 200px lets an item grow from a starting size of 200px but never shrink below it.

Flexbox is one-dimensional by design. For two-dimensional layout — where you control both columns and rows — use CSS Grid (next chapter). The two work well together.

Key Ideas

  • display: flex on a container makes its children flex items.
  • justify-content aligns along the primary axis; align-items along the cross axis.
  • flex-direction chooses row or column; flex-wrap allows wrapping.
  • flex: 1 makes items share the space equally.

Try It Yourself

  1. Make a horizontal nav bar with display: flex and even spacing.
  2. Centre a box both horizontally and vertically with Flexbox.
  3. Build a row of three equal-width cards using flex: 1.

Laying Out a Page with CSS Grid

Two-dimensional layout, with named areas that describe themselves.

CSS Grid is the tool for two-dimensional layout — you define columns and rows explicitly, then place your content within the resulting cells. It's the most powerful layout system CSS has ever had.

.container {
  display: grid;
  grid-template-columns: 200px 1fr 1fr;
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
}

The fr unit is Grid's special fraction unit — it distributes the container's free space after fixed sizes have been allocated. 1fr 2fr splits the space in a 1:2 ratio. The repeat() function condenses repeated values, and minmax(min, max) gives a column a range. auto-fit with minmax() creates responsive grids that rearrange themselves as the viewport changes:

grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));

The most intuitive way to place items is with named grid areas. You draw a text diagram of your layout with grid-template-areas, then assign each child to an area with grid-area:

.container {
  display: grid;
  grid-template-columns: 15vw 1fr 20vw;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "logo   header header"
    "nav    content sidebar"
    "footer footer footer";
}

header { grid-area: header; }
nav    { grid-area: nav; }
footer { grid-area: footer; }

Alignment inside Grid is controlled by four properties: justify-content and align-content align entire tracks within the container; justify-items and align-items align each item within its cell.

Grid and Flexbox complement each other. Use Grid for the page's overall structure; use Flexbox for the smaller components inside each region.

Key Ideas

  • display: grid on a container turns its children into grid items.
  • grid-template-columns and -rows define the layout; fr distributes free space.
  • grid-template-areas draws a text-based layout diagram.
  • repeat(auto-fit, minmax(240px, 1fr)) creates a responsive grid.

Try It Yourself

  1. Build a 3-column grid with grid-template-columns: 1fr 2fr 1fr.
  2. Draw a layout with grid-template-areas for header, sidebar, main, footer.
  3. Make a responsive card grid with repeat(auto-fit, minmax(240px, 1fr)).

Creating Responsive Layouts

Making one page look right on every screen.

A responsive page looks good and works well on any screen — phone, tablet, laptop, desktop, television. There are two complementary techniques for getting there: fluid layouts that scale smoothly with the viewport, and adaptive layouts that switch to different rules at defined thresholds.

Fluidity comes free with Flexbox and Grid. Set flex: 1 on flex items and they grow or shrink with the container. Use fr units and minmax() in Grid and columns adjust themselves. Use viewport units (vw, vh) for measurements that should scale with the window. Use clamp() to keep type from getting too small or too large:

h1 {
  font-size: clamp(1.75rem, 1rem + 2vw, 3rem);
}

Adaptation comes from media queries. A media query tests something about the viewport and applies rules only when the test passes:

@media (max-width: 600px) {
  .site-logo { display: none; }
  nav { flex-direction: column; }
}

The breakpoint at 600px is arbitrary — pick the widths where your particular layout starts to look wrong. Don't chase specific devices; chase the widths where your own design breaks.

Container queries — the newer sibling of media queries — test the width of a parent element rather than the viewport, letting components adapt to their context. And user preference queries — prefers-color-scheme, prefers-reduced-motion, prefers-contrast — let your page respect the visitor's OS-level settings.

For images, set max-width: 100%; height: auto so they never overflow their container. For higher-fidelity delivery, use the sizes and srcset attributes on <img> to let the browser pick an appropriately sized file for the current screen — saving bandwidth on phones while still delivering crisp images on desktops.

And adopt a mobile-first mindset: start by designing for the smallest screen (what's absolutely essential?), then add features and complexity as the viewport grows. It's easier, and it produces leaner pages for the majority of your visitors.

Key Ideas

  • Responsive pages combine fluid (scales smoothly) and adaptive (switches at breakpoints) techniques.
  • Use clamp(), viewport units, and fr to build fluidity into your typography and layout.
  • Use media queries at breakpoints where your layout actually breaks.
  • Respect user preferences and deliver appropriately sized images.

Try It Yourself

  1. Add a media query that hides a sidebar below 600px wide.
  2. Set a heading's font size with clamp() and resize the browser to see it work.
  3. Add max-width: 100% to all your images and confirm none overflow.
